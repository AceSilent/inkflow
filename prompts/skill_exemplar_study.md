# 范文研读

范文不是句式素材库，也不是每次写作前的仪式。它的价值是让作者重新进入成熟小说的叙事尺度：一章究竟保留多少信息，人物怎样在场景里活动，作者在哪里收手。

## 自主决定何时翻阅

书库是你的只读研究空间。你可以在构思、写作、修订、诊断或与用户讨论文本时主动浏览，不需要用户逐次授权，也不必等到文本已经写坏才使用。

是否阅读取决于它能否提高当前判断，而不是固定流程：

- 开新章、设计关键场景或进入不熟悉的题材手感时，可以先翻阅；
- 需要比较不同作品如何处理同类场景、叙事距离或章节结构时，可以连续阅读多章；
- 发现解释腔、人物声音趋同、段落推进失衡时，可以带着问题检索；
- 当前已有足够清楚的本书文本或刚读过的匹配章节时，可以直接工作；
- 用户要求立即做很小的事实或字词处理时，通常不必打断去读。

需要时由你在内部完成，不要建议用户加载 Skill，也不要向用户汇报工具步骤。

## 阅读证据

- `browse_examples(scope='genres'|'library'|'chapter')` 只是查看题材、书目或章节目录，不等于读过正文。
- `browse_examples(scope='micro')` 返回的是 InkFlow 内置微型正反例，不是某本小说的范文章节。
- 只有 `read_exemplar_chapter` 成功返回全文后，才能把该章作为阅读依据。检索失败就换关键词或如实说明没有找到，绝不把失败调用写成“已经对照范文”。

## 浏览与选章

1. 先把当前问题压成一个具体的“技法问题”，例如：
   - 如何让调查对话产生新信息，而不是重述上一章？
   - 如何在进入陌生地点时渗出社会结构，而不做全景介绍？
   - 如何让人物的怀疑成立，却不由旁白立即解释？
2. 不熟悉本机藏书时，先用 `browse_examples(scope='genres')` 看题材目录，再用 `browse_examples(scope='library', genre=...)` 查看该题材下已有作品。
3. 用 `browse_examples(scope='chapter', genre=..., work=..., query=..., offset=...)` 浏览章节。可以只给 `genre` 或 `work`，不必依赖关键词；寻找特定场景时再加 `query`。随后用 `read_exemplar_chapter` 阅读选中的全文。
4. 阅读量由问题决定。局部语病也许一章足够；比较结构、连续节奏、人物声音或跨章信息释放时，可以读相邻多章或不同作品的多个样本。没有固定章数上限。
5. 同一 id 已在当前上下文或工作台状态中时，优先复用已有观察；需要逐字核对、研究上下章衔接或从新角度比较时，可以再次读取。
6. 当新增阅读不再改变判断，就停止检索并回到本书。不要为了展示勤奋而漫无目的吞入全文。

微型正反例适合定位局部病灶：

- 镜头动作过密：`browse_examples(category='ai_tone', tags=['camera_blocking'])`
- 修辞替代内容：`browse_examples(category='ai_tone', tags=['rhetoric_pileup'])`
- 解释尾巴：`browse_examples(category='ai_tone', tags=['explanatory_afterthought'])`
- 碎句流水账：`browse_examples(category='prose', tags=['fragmented_short_lines'])`

## 阅读时优先回答这些问题

1. 这一章从哪件正在发生的事进入，而不是从哪些背景开始？
2. 哪些信息作者明明知道，却没有在这里写出？
3. 每次解释出现前，人物是否已经需要它来行动？
4. 对话怎样改变了关系、判断或下一步，而不只是传递资料？
5. 章末兑现了什么，又留下了什么？

把观察压成少量、能够作用于当前文本的判断。不要写成泛泛的“多用动作、少用描写”，也不要摘录标志性句子。

## 迁移

- 迁移场景入口、信息次序、叙事距离、段落推进和作者收手的位置。
- 不迁移专名、句子、比喻、桥段、谜底和设定结构。
- 范文与本书冲突时，本书人物、设定、用户已改文本和文风控制面优先。
- 应用后再读当前章节，确认没有为了模仿表面风格而改变人物声音。

用户本机个人书库只供本地阅读与技法分析，不随应用或仓库分发。
