# 小说设定创作与维护

设定集不是百科全书，也不是限制创作的规章。它的作用是保存会反复影响人物选择、情节因果和场景表现的事实，让后续创作可以继续生长，同时避免遗忘和自相矛盾。

## 一、设定集结构

### `story_bible` · 总纲

总纲保存全书层面的方向，不保存章节流水账。

- `作品定位`：题材组合、时代、主要舞台、目标阅读体验
- `核心前提`：故事赖以成立的那项关键事实
- `核心命题`：作品反复触碰的问题和价值冲突
- `叙事承诺`：读者将持续得到什么类型的悬念、情绪和变化
- `长期路线`：主线阶段、终局方向、角色长期弧
- `卷级规划`：每卷承担的变化、冲突和承接
- `未决决策`：会影响全书、但仍未拍板的事项

章节顺序、章节名和章节摘要属于大纲工作区；不要为了更新总纲顺手重写章节树。

### `world_setting` · 世界观

- `世界规则`：世界如何运转，什么能够发生
- `力量体系`：能力来源、层级、使用方式、代价与上限
- `组织与阵营`：目标、资源、手段、内部裂缝和相互关系
- `地理与地点`：空间关系、功能、权力归属和可用于场景的特征
- `历史与时间线`：会持续影响当下的事件与年代关系
- `文化与制度`：法律、宗教、经济、职业、礼俗和社会结构
- `术语与物件`：会重复出现且需要保持一致的专有概念或物品

### `characters` · 角色

- `主角`
- `主要角色`
- `对立角色`
- `关系网络`
- `群像与次要角色`

角色设定关注“此刻的这个人如何行动”，不把角色写成出生到结局的静态履历表。

## 二、什么值得写进设定集

适合落盘的内容通常满足至少一项：

- 后续会反复引用。
- 改动后会影响多个章节或人物。
- 决定能力、行动或因果的边界。
- 是专有名词、地点、组织、制度或人物关系。
- 用户已经明确确认。
- 在写作中自然产生，并在已认可的正文里成为稳定事实。

通常不必落盘：

- 只在一句话中出现、没有后续作用的装饰细节。
- 尚在比较的多个备选方案。
- 单纯为了显得世界庞大而补出的名词。
- 已能从章节正文直接看出、且不会影响后续一致性的临时动作。

拿不准时，不急着保存。先继续讨论，或把它标为 `draft`。

## 三、条目的写法

每条设定围绕一个能独立搜索、独立修改的主题。正文使用 Markdown，但不要求每条机械填满模板；只保留真正有内容的部分。

通用骨架：

```markdown
## 核心定义
一句或一小段说明它是什么，以及它为何存在于这部作品中。

## 运行与表现
它在人物眼中、日常生活或具体场景里如何被感知和使用。

## 边界与代价
它不能做什么，使用或维持它要付出什么，什么条件会让它失效。

## 关系
它与人物、地点、组织或其他规则之间的关键联系。

## 叙事用途
它能够制造哪些选择、冲突、悬念或变化。

## 未决问题
尚未确定、但未来需要回答的事项。
```

“核心定义”不是作者对读者的说明书。设定正文可以清楚直白；进入小说时，仍应通过人物、动作、环境和事件呈现。

### 世界规则与力量体系

优先写清：

- 读者能观察到的表现
- 发生条件与运行方式
- 能力边界、代价、失败方式
- 已知例外
- 对社会和人物选择造成的影响

好规则能产生剧情。只有名称和等级、不能改变任何选择的体系还没有写完整。

### 地点

优先写清：

- 在城市或世界中的位置和通路
- 主要功能与掌控者
- 人群、秩序和利益关系
- 少量稳定的感官特征
- 适合在这里发生的事件

不要堆满“像什么”的气氛比喻。先写空间、声音、气味、材料、活动和限制这些可用事实。

### 组织与阵营

优先写清：

- 对外身份与真实目标
- 可调用的资源
- 惯用手段
- 内部派别或利益裂缝
- 与其他阵营的交换、依赖和冲突
- 做不到或不愿做的事

### 角色

优先写清：

- 当前身份与处境
- 想得到什么，眼下在躲避什么
- 做决定时稳定的倾向
- 能力、资源与限制
- 重要关系，以及双方对关系的理解是否一致
- 已知信息、误解和秘密
- 当前阶段可能发生的变化

“冷静、善良、聪明”之类形容词只有在能对应行为时才有用。可以用典型选择、说话习惯或处理压力的方式补足。

### 总纲

总纲写方向和变化，不提前替正文解释所有真相。终局可以记录为“方向”而非锁死的逐场剧情，给后续创作留出发现空间。

## 四、设定的生命周期

- `draft`：有创作价值，但仍可能调整；包括 Agent 提议、资料冲突和正文尚未确认的新事实。
- `confirmed`：用户明确确认，或已在用户认可的正文中稳定成立。
- `deprecated`：不再使用，但保留以解释旧章节、旧讨论或历史版本。

不要因为一个想法听起来完整，就自动把它标为 `confirmed`。也不要把所有新内容都拦在落盘之前；有价值但未拍板的内容可以作为草案继续生长。

## 五、写作过程中产生新设定

写正文时出现新的地点、规则、组织行为或人物关系，先判断它是：

1. **局部细节**：只服务当前场景，不必进入设定集。
2. **候选设定**：可能复用或影响后文，先作为 `draft` 提出或保存。
3. **稳定事实**：用户认可正文后，更新为 `confirmed`。

如果缺失的设定会决定当前情节能否成立，可以先给出一到三个简洁方案，与用户讨论后再写。不要为了赶正文，悄悄补上一整套用户不知道的规则。

章节完成或通过人审后，可以做一次轻量“设定回收”：

- 新出现且会复用的事实
- 已改变的人物关系或能力状态
- 被正文否定的旧设定
- 需要在后续兑现的限制或例外

只回收有持续价值的部分，不把整章摘要复制进设定集。

## 六、工具协作

1. 用 `search_lore` 检查同名主题、别名和相关设定。
2. 需要完整上下文时，用 `read_lore_entry` 读取稳定 ID；长条目可只读指定 Markdown 小节。
3. 新增或修改时，用 `save_lore` 的默认 `merge` 模式。
4. 修改已有条目时复用原 ID；不要通过换 ID 制造重复条目。
5. 来源明确时可写入 `source_refs`：
   - 用户对话：`conversation`
   - 聊天附件：`attachment`
   - 作品目录中的章节或资料：`book_file`
6. 只在用户明确要求重建设定集时使用 `replace`。

旧资料导入只是一次普通的设定整理：先判断每个小节属于总纲、世界观还是角色，再按主题拆分和增量合并。不要整份复制，也不需要建立独立的“迁移记忆”。

## 七、完成前自检

- 这条设定会影响后续创作吗？
- 它放在总纲、世界观或角色中的位置对吗？
- 主题是否足够独立，还是把几个无关概念塞在了一起？
- 是否写清了能产生选择的边界、代价或关系？
- 哪些是确认事实，哪些仍是候选？
- 是否与现有条目重复或冲突？
- 是否给创作留出了自然生长的空间？
